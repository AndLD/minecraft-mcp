# Phase 27: Excavation reliability

_Estimate: 1½ sessions._  
**Status:** done on `feature/excavation-reliability` (the branch is named after the feature, not `fix/excavation-reliability`). The seal bug was theory 2 (a cavern through the floor); a chest in the footprint only ends its own column. `dig_to` shipped in the same branch. Details in [Excavation](../../features/world/excavation.md).

**Depends on:** [14 Excavation and mining](excavation-mining.md), [15 Structured gathering: pits and quarries instead of scattered holes](structured-gathering.md).  
**Needed by:** [28 Excavating upward and continuing an existing dig](excavation-upward.md) (optional: a continued dig most needs the verification pass).

Three problems found in live sessions, all in the excavation shapes, written up under "Known issues" in [Excavation](../../features/world/excavation.md): cave sealing put blocks inside a quarry at random and nothing checks the result, gravel and sand stop a dig for good, and there is no way to dig a route to a specific ore.

- Branch: `fix/excavation-reliability`. Remove each known-issue bullet from the feature document as it is fixed.
- **First, reproduce the cave sealing bug** before changing the seal pass, in a Docker e2e that reads the block grid back afterwards. Two theories, neither confirmed: (1) the player asked for a chest inside the quarry during that run, which may have thrown off the seal pass's bookkeeping of which open cells are the cave and which are plan cells still to be dug; (2) the cave did not only touch a wall but cut through the quarry's floor (a cavern larger than the footprint), and the seal pass placed blocks at cells the plan counts as dug. The fix follows from which one it is (or both).
- **A verification step for every shape** (quarry, pit, shaft, tunnel, branch mine, staircase, room), after the dig and the sealing, that reads the result back and checks that it **(1) matches the planned shape, (2) is sealed where sealing was asked for, (3) holds no extra blocks** (cobblestone, dirt, or anything else that is not in the plan). Extra blocks are cleared. **Special blocks are never touched**: chests and other containers, crafting tables, furnaces, torches, ladders, signs, doors, beds, and anything else that is meant to be there or that the player placed. The result reports what it checked and what it cleaned up, and a shape that still does not match says so (`verification_failed` with the cells) instead of ending as success.
- **Gravel and sand (`falling_blocks`).** Today the hazard rule ends a chain when the cell above the block about to be broken is sand or gravel, and running it again changes nothing. Options in the known issue: dig the falling column so it settles (break the gravel, stop the rest with a torch or a block, and continue), or dig gravel and sand cells as part of the plan with a short wait for the fall to settle. Add `falling_blocks: 'clear'` to `excavate`, after the safety check for lava and water beyond, and report the **exact blocking cells** in `ended` so the player or the agent can clear them. Also handle the related symptoms: the hazard triggering when the gravel lies over a cell that is itself still to be dug, and `collect_block` answering `unreachable` with no hint that a dig stopped on gravel.
- **`dig_to`.** A route dug to a specific target block (an ore vein, a chest), using the same hazard rule, so the agent does not compute an origin by hand and `collect_block` does not refuse ore it cannot walk to (`not_reachable_without_tunnelling`). It is a new shape provider (a new file, registered in the composition root), not a change to the others. If it grows, split it into its own branch.
- Tests:
  - unit: the verification pass over a block grid (matches, a missing cell, an extra cobblestone cleared, a chest left alone, a torch left alone, a failing check reported), the seal pass in the two cave cases (a cavern through the floor, a chest in the footprint), `falling_blocks: 'clear'` (gravel column settles, lava beyond refuses, blocking cells reported), `dig_to` (route, hazard rule, unreachable target)
  - integration: `excavate` through the tool layer on a fake world with a cave under the footprint and a placed chest: the result is verified and clean
  - e2e: a quarry over a real Paper server whose floor a cavern cuts through, a chest placed inside, and a gravel column over a staircase: the final grid matches the plan, the chest is still there, and `dig_to` reaches an iron block set behind rock
- **Exit criteria:** a quarry dug over a cave has no stray blocks inside and the run says it verified the shape; a dig through gravel finishes or names the cells that stop it; "dig to that iron" digs a safe route to it.
