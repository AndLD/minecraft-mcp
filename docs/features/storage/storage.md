# Storage

**Depends on:** [Persistent state](../core/persistent-state.md), [Tasks](../core/tasks.md).  
**Used by:** [Cave exploration](../world/cave-exploration.md) (torches from storage), [Gathering, crafting, smelting](../gathering/gathering-crafting-smelting.md) (fuel from storage), [Gathering, crafting, smelting](../gathering/gathering-crafting-smelting.md) (optional), [Hunting and food](../gathering/hunting-and-food.md) (optional), [Handing items over](handing-items-over.md), [Construction and building](../world/construction-and-building.md), [Excavation](../world/excavation.md) (optional), [Railways](../world/railways.md) (optional), [Crop farming](../farming/crop-farming.md) (optional), [Egg collection](../farming/egg-collection.md) (optional).

- `ContainerIndex` remembers containers per world (position, block, optional unique label, `protected`, `auto` when found by scanning, last-seen contents and free slots, when it was opened). Registering a known place, or the other half of a double chest, updates the entry instead of adding one. `StorageRules` map item names or groups to a container with a priority; `StoragePolicy` is the standing answer for a full inventory (`ask` default, `offload_and_return`, `stop`, plus `maxTrips` and `maxDistance`).
- **Item specs** (`src/skills/storage/item-matcher.ts`) are exact item names or groups (`*`, `logs`, `planks`, `wood`, `stone`, `ores`, `ingots`, `food`, `tools`, `armor`, `blocks`, `wool`, `dyes`); adding a group is a line in one table. **Reserved items** (tools, weapons, armor, food, torches, buckets) are never deposited unless named by exact name or `include_reserved`.
- `ContainerSelector` (swappable strategy): the first rule that matches (highest priority first) wins and is used wherever the container is; otherwise the nearest known container with room within `maxDistance`; otherwise a nearby container nobody registered (registered on use). Protected containers are never chosen, for depositing or withdrawing.
- `ContainerVisitor` walks to a container, checks the block is still one (a vanished container is removed from the index), opens it, records the contents before and after, and closes it. `DepositItemsSkill` groups items by target, visits nearest first, skips full or failed containers and retries the rest elsewhere, and reports what did not fit (`no_storage_space` when nothing fit). `WithdrawItemsSkill` reads what a container really holds (the index may be stale). `ScanContainersSkill` refreshes and registers (`skipProtected` leaves protected containers unopened; the cave torch supply uses it); `FindItemsSkill` answers from memory and scans when memory has nothing.
- **Moving items is done by clicking, not with Mineflayer's `deposit`/`withdraw`** (same reason as crafting: they predict clicks and the 1.21 server ignores stale ones). `WindowTransfer` shift-clicks whole stacks, moves part of a stack with single right-clicks, and syncs with the server after every step; a shift-click that seems to have moved nothing is only believed after four looks, because a sync can be answered by an older update (found by the e2e test: a 100-item deposit stopped after one stack). The window comes from `bot.openContainerWindow`, installed after spawn by `installContainerWindows`.
- **Full inventory.** `InventoryFullHandler` is used by `collect_block` and `hunt_animals` (per-call `on_inventory_full`, else the standing policy): `stop` ends the task; `offload_and_return` deposits everything that may be deposited, walks back to where the bot stood, and continues (up to `maxTrips` per task, then it asks); `ask` pauses the task. When offloading fails (no container with room), it falls back to asking, with the reason in the question. `hunt_animals` with `cook` and `deposit_cooked` puts the cooked meat into a container by the storage rules.
- **Pausing a task** (`waiting_for_input`): a skill calls `context.ask({ message, options })`; the task keeps its slot, shows the question in `get_task_status` (`waitingFor`), and the app pushes a `needs_decision` event. `resume_task` answers with one of the options (`TaskManager.answer`); a cancel resolves the question with undefined. Tools return at once when a task starts waiting, so the agent does not sit out its wait budget.
- **Organizing what is already in the chests** (`organize_storage`, `OrganizeStorageSkill`). "Sort my storage": every stack that a rule sends to another container is carried there. `ContainerSelector.ruled(item)` gives the rule-only answer (no "any chest with room" fallback), so items with no rule stay where they are (`unchanged`, with the stacks already in the right place). The skill first **looks into** the chosen containers and every rule target (so the plan comes from what is really inside, which also refreshes the remembered free space), then **plans** every move against the room each container will have (free slots plus the room in a partly full stack, counting what earlier moves take and free; a second and third pass use room that was freed), then **carries out** one trip per source: it takes out what fits in the inventory (two slots are always kept free), delivers it to each destination, and puts back into the source whatever a destination refused. `dry_run` defaults to **true**: it only reports the plan (`moves`, `left`, `skipped`, `unchanged`), so the agent shows it to the player and asks before the real run. Options: `containers` (ids or labels to sort; every known one by default, but items are delivered to any rule target), `max_minutes`. Result: `moves` (what really moved, with counts), `moved`, `left` (with a reason: no room, inventory full, container gone, time), `skipped` (protected, unreachable), `carried` (anything still in the bot's hands). A cancel puts carried items back first. Protected containers are never opened, as sources or destinations, and nothing is thrown away. It does not craft chests or handle ender chests and carried shulker boxes.
- Registering by "the chest I am looking at" casts a ray from the owner's eyes (`bot.world.raycast`, missing from Mineflayer's typings, so `world` is excluded from the compile-time guard in the factory).
