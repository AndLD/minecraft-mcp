# Egg collection

**Depends on:** [Animal farming](animal-farming.md), [Gathering, crafting, smelting](../gathering/gathering-crafting-smelting.md), [Storage](../storage/storage.md) (optional).  
**Used by:** no other feature directly.

Phase 18's third sub-branch (`feature/egg-collection`), a follow-up split out of `feature/animal-farming`'s own scope once that branch merged (the plan described eggs as part of animal farming, "after breeding", but the rest of that branch was already large). Reuses the pen and species infrastructure `feature/animal-farming` built (`FarmRegistry`, `AnimalPenProvider`, `HerdManager`) unchanged; nothing here touches an animal directly, only ground items.

- Branch: `feature/egg-collection`. No new ports: eggs are picked up with the existing `DropCollector` (gathering) and thrown with the existing `InventoryWriter`/`Gaze` ports `give_items`' drop mode already uses — confirmed by research before writing any code that `InventoryWriter.toss('egg', 1)`, called once per egg, is already the correct primitive for "throw exactly one at a time" (its `WindowDropper` backing takes the single-click code path for `count === 1`), so no new low-level port method was needed.
- **`EggThrower`** (`src/skills/farming/egg-thrower.ts`) is a small, purpose-built class, not a reuse of `ItemThrower` (`give_items`'s own thrower): `ItemThrower` batches a whole stack per call with a pause between *items*, not units, and never calls `Gaze` at all, whereas throwing eggs into a pen needs a fresh look at the target cell before **every single egg**. `EggThrower.throw(count, target, signal)` loops `count` times: `Gaze.lookAt(target)`, then `InventoryWriter.toss('egg', 1)`, then a short pause (`PAUSE_MS`, matching `ItemThrower`'s own pacing), stopping early on abort or once the inventory runs dry (`toss` returning 0).
- **`CollectEggsSkill`** (`collect_eggs`) sweeps a registered pen or a given area for `egg` drop items with `DropCollector`, scoping the sweep with a `maxDistance` computed **from the bot's own current position to the area's centre, plus a margin** — confirmed necessary because `DropFilter.maxDistance` is bot-position-relative, not area-relative (there is no "search near this other point" on `DroppedItemScanner`, the same limit `WallTarget`/`MarkerFinder`/`SwitchFinder` already live with), so the actual area filtering happens in the `accept` predicate, not the distance. That predicate also excludes anything inside a **protected area that is not the pen's own**: `register_farm`-registered pens get no automatic `ProtectedAreas` entry (only `build_farm`-built components do, via `BuildFarmSkill`'s own `protectedAreas.add()`), so `allowedHere()` checks `ProtectedAreas.protectedAt(position)?.label === (farm.label ?? farm.id)` rather than assuming every pen is protected.
- **The split between storing and releasing** follows `EggPolicy` (`storeFraction`, default 0.1, rounded up so any pickup keeps at least one; `release`, `'hatch'` default or `'store'`) unless the call overrides it. The stored share is deposited through the ordinary `ItemDepositor`/storage rules (`DepositItemsSkill`'s `count` field caps correctly here because `specs: ['egg']` is always a single exact match); the rest is thrown into the pen's centre with `EggThrower`, capped by how much room the pen has left against `max_chickens` (explicit input, else the farm's own `herdTarget`, else a rough `penCapacity(width, length)` reused from `AnimalPenProvider` as a last resort) minus the chickens already counted inside the bounds — a pen already at target throws nothing and reports `penFull: true` (a shortfall, like `lure_animals`'s, not a failure).
- **`EggPolicy`** (`src/state/egg-policy.ts`) is a small `ProfileScoped` state class holding `{storeFraction, release}`, following `StoragePolicy`'s object-valued shape (not `FoodPolicy`'s plain enum, since there are two independent settings here). `set_egg_policy` saves it and mirrors a non-default choice into `StandingInstructions` (`egg_policy`), exactly like `set_food_policy`.
- **Wired into `tend_farm`:** `TendFarmSkill`'s pen branch runs `CollectEggsSkill` after `HerdManager`, but only when the pen's species is `chicken` and a `CollectEggsSkill` is wired in (an optional dependency — a pen tended without one is just herded, unchanged from `feature/animal-farming`). The three new result fields (`eggsPickedUp`, `eggsStored`, `eggsReleased`) are `undefined` for a field or a non-chicken pen. `problem` reports egg collection's own failure only when herding itself succeeded, so a real herding failure is never masked by a knock-on egg-collection one.
- **Gotcha found by this feature's own e2e test, not simulable in a fake:** summoning a dropped item stack by RCON (`summon item ... {Item:{id:"minecraft:egg",Count:10b}}`, the pre-1.20.5 item-entity NBT shape already used for mobs elsewhere in this codebase) silently produced a single egg, not ten — Minecraft 1.20.5's data-component rewrite also changed a dropped item entity's own `Item` tag from `Count` (a byte) to `count` (a plain int, lowercase). The working form, `{Item:{id:"minecraft:egg",count:10},PickupDelay:0}`, already existed in `test/e2e/gather-craft-smelt/gather-craft-smelt.e2e.test.ts` for a dropped apple stack; this feature's test now matches it. **A second, unrelated gotcha, matching the established e2e pattern:** a chest set by RCON right before `register_container` failed with "That is air, not a container" — the classic "RCON changes reach the bot a moment later" issue (AGENTS.md's own e2e conventions), fixed by polling `find_blocks` for the chest before registering it, the same wait pattern `storage.e2e.test.ts` already uses.
- **Not built, per the plan:** `discover_farm` (built later, see [Discovering farms](discovering-farms.md)).
- **Tests:** unit — `EggPolicy` (`test/unit/state/farm-state.test.ts`, mirroring `StoragePolicy`'s own attach/get/set/detach/persistence pattern rather than `FoodPolicy`'s plainer one, since `EggPolicy`'s value is an object), `EggThrower` (looks before every single egg, stops early when the inventory runs out, stops on an already-aborted signal, throwing zero does nothing), `CollectEggsSkill` (splits picked-up eggs by the default and an overridden policy, `release: 'store'` throws nothing, an explicit `max_chickens` overrides the farm's own `herdTarget`, falls back to the rough pen-capacity figure with no farm given, skips an egg inside a protected area that is not the pen's own while still counting one inside the pen's own protection, reports zero without touching storage or throwing when nothing was picked up, `no_area` and `not_connected` failures), the two tools' input translation and the standing-instruction mirror/clear behaviour (`test/unit/mcp/tools/farming-tools.test.ts`), `TendFarmSkill`'s pen branch (collects eggs only for a chicken pen and only when the dependency is wired in, merges the three counts into the result, reports egg-collection's own failure only when herding succeeded, reports herding's failure instead when both fail)
  - integration: the two new tools registered and counted in `test/integration/create-app.test.ts` and `test/integration/mcp-flow.test.ts`'s tool listing
  - e2e (extends `test/e2e/farming/animal-pen.e2e.test.ts`): a registered chicken pen with ten egg items summoned inside it and a registered chest nearby: `collect_eggs` picks up all ten, stores exactly one (the default 10%, rounded up) in the chest, and throws the rest, leaving none in the bot's own inventory
- **Exit criteria:** "collect the eggs" picks up everything lying in the pen, stores a tenth in a chest, and throws the rest in for chicks (unless told otherwise, or the pen is already at its target chicken count); "keep half the eggs" (`set_egg_policy`) changes the split from then on without asking again; running `tend_farm` on a chicken pen breeds or culls it and collects its eggs in the same pass, one summary.
