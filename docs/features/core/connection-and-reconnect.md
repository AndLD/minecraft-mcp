# Connection, reconnect, and hardening

**Depends on:** [Chat and events](chat-and-events.md) (the events the agent reads), [Tasks](tasks.md) (a lost connection cancels the running task), [Persistent state](persistent-state.md) (the world is opened again after a rejoin).  
**Used by:** nothing yet.

`feature/hardening` ([Phase 48](../../DEVELOPMENT-PLAN/phases/hardening-polish.md)).

- **Rejoining** (`ReconnectSupervisor`, `MC_RECONNECT_ATTEMPTS`, default 6, `0` turns it off). When the connection is **lost** (the server restarted, the network dropped, a LAN world was closed and opened again) the supervisor waits 5, 10, 20, 40, then 60 seconds between attempts and calls `SessionService.connect` for the same host and port, so the world's saved state is opened again like at any join. It does **not** rejoin after a `disconnect` or a shutdown (`ConnectionEvent` `disconnected` carries `intentional: true` then), nor after a kick (a ban or a whitelist would only repeat; the `kicked` event is remembered until the bot is back), and it stops when somebody connects by hand. It never resumes a task: the tasks that were running were cancelled when the connection dropped and are recorded as interrupted, and the agent decides, as after a restart.
- **What the agent hears** (events in `wait_for_chat`): `disconnected`, `reconnecting` (how many attempts, and that nothing resumes by itself), `connected` and `reconnected` (look at `get_session_briefing` for interrupted tasks first), or `reconnect_failed` (ask the player whether the world is open, then call `connect`). `wait_for_chat` **keeps waiting** while the supervisor is retrying instead of failing with "not connected", so a listening loop survives an outage; it fails again once the supervisor has given up or was never on.
- **Timeouts on every I/O boundary** (audit, nothing had to change): joining (30 s), leaving (3 s), the server status probe (3 s), LAN discovery (its own timeout), walking (a base time plus a time per block), server commands (a reply timeout); window clicks and opens rely on Mineflayer's own 5 and 20 second limits; every skill takes an `AbortSignal`, and `TaskManager` releases a task that does not honour a cancel, so no task stays stuck after a cancel or a lost connection.
- **Tool descriptions.** `test/integration/tool-descriptions.test.ts` reads the tool list as the agent sees it and fails when a tool name is not snake_case, a description is under 40 or over 2600 characters, or any argument (nested ones too) has no description. It found four things, now fixed: `forget` and `remove_storage_rule` had one-line descriptions with no failure mode, and `flatten_area` and `preview_flatten` had an `origin` whose `x` and `z` were unexplained.
- **Not done in this branch:** the 30-minute co-play session on a real world (it needs the player and their LAN world, so it is theirs to run), the agent playbook rewritten from real sessions (the start prompt was brought up to date with the rules and events instead), and a written cross-review of the hazard, light, and drop rules (they are covered by each feature's own tests and pages).
- **Tests:** unit — the supervisor (the delay of each attempt, giving up, intentional and kicked disconnects, stopping when connected by hand, off, no target, `reconnecting`), the `intentional` flag from the connection, the config; integration — rejoining after the socket closes with a task running, the task not stuck, `wait_for_chat` waiting during the outage, no rejoin after `disconnect` or a kick, the tool-surface audit; e2e (`test/e2e/reconnect/`) — a connection pulled on a real server is rejoined and the bot is usable again, and a kicked bot stays out.
